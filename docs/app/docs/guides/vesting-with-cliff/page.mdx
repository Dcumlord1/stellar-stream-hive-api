# Vesting with a One-Year Cliff

A cliff is a withdrawal gate, not a pause in accrual. In this example, a
12,000 XLM grant vests linearly over four years. Nothing can be withdrawn
before the first year has passed; at the cliff, the first year's accrued 3,000
XLM becomes withdrawable at once. The rest continues vesting through year
four.

## Convert the schedule to ledgers

The schedule below uses 365 days per illustrative year and the documented
estimate of 5 seconds per ledger:

```text
seconds per day = 86,400
ledgers per day = 86,400 / 5 = 17,280
one-year cliff  = 365 * 17,280 = 6,307,200 ledgers
four-year term  = 4 * 6,307,200 = 25,228,800 ledgers
```

Let `S` be the ledger chosen for the stream's start. For the arithmetic
examples, use `S = 1,000,000`:

| Schedule point | Ledger |
|---|---:|
| Start | `S = 1,000,000` |
| One-year cliff | `S + 6,307,200 = 7,307,200` |
| Four-year end | `S + 25,228,800 = 26,228,800` |

These ledger sequences are illustrative, not deployment or current-ledger
claims. For a real stream, read the current ledger and select valid future
ledgers. Five seconds per ledger is an estimate; calendar anniversaries and
actual ledger close times can differ, especially over a multi-year schedule.
The [date-to-ledger explanation](/docs/concepts/streaming-math#converting-dates-to-ledgers)
covers this limitation.

## Create the stream

For XLM, `total_amount` is in stroops (7 decimal places). The example amount is
`12,000 * 10,000,000 = 120,000,000,000` stroops. Substitute real account and
token values and a start ledger appropriate for the network; the angle-bracket
values below are placeholders, not contract addresses.

```bash
stellar contract invoke \
  --id <STREAM_CONTRACT_ID> \
  --source sender \
  --network testnet \
  -- create_stream \
  --sender <SENDER_ADDRESS> \
  --recipient <RECIPIENT_ADDRESS> \
  --token <TOKEN_CONTRACT_ID> \
  --total_amount 120000000000 \
  --start_ledger 1000000 \
  --end_ledger 26228800 \
  --cliff_ledger 7307200 \
  --cancellable true
```

The example's schedule fields are `start_ledger = S`,
`end_ledger = S + 25,228,800`, and `cliff_ledger = S + 6,307,200`.
`cancellable` is fixed at creation: `true` lets the sender cancel an eligible
pending or active stream; `false` does not. Choose it to match the grant terms.

## Check what is withdrawable

The Stream contract calculates accrued value from the start, using
`total_amount * elapsed / total_duration` with integer division. It then
returns zero as withdrawable while the current ledger is before the cliff;
once the cliff is reached, the already-accrued amount becomes available. With
no previous withdrawals:

| Point | Current ledger | Streamed (stroops) | Withdrawable (stroops) |
|---|---:|---:|---:|
| One ledger before cliff | `7,307,199` | `29,999,995,243` | `0` |
| At cliff | `7,307,200` | `30,000,000,000` | `30,000,000,000` |
| One ledger after cliff | `7,307,201` | `30,000,004,756` | `30,000,004,756` |

At the cliff, the result is
`120,000,000,000 * 6,307,200 / 25,228,800 = 30,000,000,000` stroops, or
3,000 XLM. The one-ledger-after amount is floored to a whole stroop by the
contract's integer division. If the recipient has already withdrawn funds,
subtract the `withdrawn` total from `streamed_amount` after the cliff; before
the cliff, withdrawable remains zero.

Only the recipient can withdraw. If the stream is cancellable, the sender can
cancel it before completion: accrued value at the cancellation ledger remains
the recipient's share, and the unstreamed remainder is refunded to the sender.
A cancellation before the cliff gives the recipient zero and refunds the full
amount. The parameters do not add milestone approvals or claw back amounts
already withdrawn. See [Streaming Math](/docs/concepts/streaming-math) for the
formula and cancellation details.
